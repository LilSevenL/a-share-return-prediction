## 为什么这样分配

项目目标仍是下一交易日开盘至第5个未来交易日收盘的收益。因此，把研究名额更多分给短周期价格行为、波动和流动性；财务、估值作为较慢的企业状态和风格背景；条件筛选是一种构造方法，不能包办全部信息来源。

下表数量是基于目标周期、信息多样性、本地数据条件和实现成本作出的**初始研究预算**，不是行业统一标准，也不是经过本项目实证确认的特征重要性。不能用数量作为回归系数、训练样本权重或持仓权重。

## 统一符号与计算规则

- `t`为信号日；只在收盘后使用当日完整数据，最早下一交易日开盘执行。
- `O,H,L,C`为同一复权口径的日开高低收；`r=log(C/LAG(C,1))`，`ri=log(C/O)`，`ro=log(O/LAG(C,1))`。相邻收益要求相邻市场交易日，停牌缺口不得被当作单日收益。
- `volume`为daily.vol原单位（手）；`amount_yuan=daily.amount*1000`；`net_flow_yuan=moneyflow.net_mf_amount*10000`。资金流表的买卖额统一转为元再与其他表混算；同表金额比值可直接使用同一原单位。
- `raw_close/raw_pre_close`为daily原始收盘价/数据源前收盘字段，用于不动价日期比例，需复核除权日口径。它只是日线流动性代理，不是停牌判定。
- `TR=max(H-L,abs(H-LAG(C,1)),abs(L-LAG(C,1)))`。
- `SUM/MEAN/STD/MIN/MAX/CORR/COV/VAR`的窗口均含t，默认要求完整连续市场日和相应有效观测。`STD/VAR/COV`采用样本分母；样本数不足、常数相关、分母0、非正对数、无穷值全部置空，不自动补0或除以任意微小数。
- `LAG(x,k)=x[t-k]`，窗口的嵌套计算需要足够额外历史。`OLS_SLOPE/OLS_R2`为窗口内有截距的时间趋势回归；时间索引0到w−1。
- `QUANTILE`使用线性插值；`KURT_EXCESS`为去偏超额峰度，至少4点；`MEDIAN_WINDOW`是同一个窗口的中位数，不是逐日滚动中位数再嵌套。
- `TSRANK(x,w)=(当前值在w个观测中的平均秩−1)/(w−1)`，并列取平均；`TSZ=(当前值−窗口均值)/窗口样本标准差`。时序标准化只用当日及以前数据。
- `MAX_STREAK`为该窗口内最长连续满足条件的市场日数量，0收益打断连涨/连跌。`MEAN_LOWEST`按收益升序选k点后平均。
- 最大回撤为窗口内峰值在先、谷值在后的最大`1-C_valley/C_peak`。Ulcer使用同一窗口中每个日期截至该日的运行最高价，不能用之后出现的最高价反推过去回撤。
- `Q(x)`是同一信号日股票池内`(平均秩−0.5)/有效股票数−0.5`，至少20个有效股票；单个缺失保留缺失。全部相同时Q=0。它只为组合构造提供可比尺度，不表示加入一个新独立信息源。

## 市场、资金流和财务的特殊口径

- `rm`为当日可观察研究股票池中有效单日收益的等权平均；股票池须使用截至该日已上市且可观察的信息，退市覆盖另行审计。`market_median_turnover`为同一股票池当日换手率中位数。
- `alpha60,beta60`为有截距的过去60个有效连续市场日市场回归参数。每个日期的`e[d]=r[d]-alpha60[d-1]-beta60[d-1]*rm[d]`，拟合不含d。X组固定事前Beta收益使用窗口开始前的Beta，区别于每天更新Beta的残差动量。
- 市场上涨/下跌捕获率在完整w日窗口中按`rm`符号筛选，至少3个符合条件的日期；条件分母为0则缺失。
- `buy_all/sell_all`分别为小、中、大、超大四类买入/卖出金额之和；`SUM_ACROSS_SIZE`只在这四类之间求和，不是时间求和。
- **大单不等于机构身份，净流入最高也不一定为正。** 日线资金流不提供真实投资者身份。
- `PIT`：对信号日只能读取`ann_date < t`的可见版本。按`end_date`定位不同季度，q为当时最新可见报告期，`q-4`指同季上年，不是“前四条数据库记录”。更正公告只能在其发布之后生效。
- 报告变化、斜率和稳定性要求同指标同会计口径；时点比率、单季、累计、TTM不能混用。跨季度变化若需要将累计指标转换为单季/TTM，必须先核对原始财表和计算口径，否则该候选不启用。不能靠补值凑满45个财务候选。
- 财报前1季变化可能有季节性，需与前4季变化分别验证。8报告期统计要求8个连续不同季度，不能把按日向前填充的同一报告当作8次观测。
- `financial_report_age`为自然日年龄；`latest_visible_ann_date`按上述PIT规则选取。含财务字段的I组也继承同样的可见性门槛。

## 条件筛选的精确定义

`TOP_HALF(x,w)`在过去w个连续市场交易日内（含t），按x升序、再按日期升序排序，取后w/2个日期。要求全部w个x有效，全部相同则缺失；选中日的相应收益必须全部有效。

最高成交量/金额/换手率或大单流入额日期并不一定是最高收益日期。筛选累计收益是条件统计量，不等于跳过其他日期后能实现的策略收益。`CORR_SELECTED`在选中的相同10天上计算ro与ri的样本相关。

本组只保留3个窗口（10、20、60）和两类核心统计，不再同时枚举高组、低组、各类收益和大量统计。旧代码中有30个同名条件因子可待核对后复用；其余5个为新增定义。

## 数据可行性

已读取本地Parquet样例schema核对：

- 日线与复权字段由原V1流程使用；OHLC、成交量/额能支持主要M/R/L/P方向。
- daily_basic包含pe_ttm、pb、ps_ttm、dv_ttm、total_mv、circ_mv、turnover_rate、turnover_rate_f、volume_ratio。
- moneyflow包含四种订单规模的买卖金额与net_mf_amount。
- fina_indicator包含roe、roa、grossprofit_margin、debt_to_assets、current_ratio、netprofit_yoy、or_yoy、ocf_to_or、netprofit_margin、assets_turn、quick_ratio。

**字段存在不等于历史覆盖完整或PIT可靠。** 尚未对新500个逐列计算或完成全历史可用性审计。新库不依赖尚未确认的分钟、盘口、历史行业成分、分析师预期或新闻数据。真实盘中路径保留到未来单独扩展，不用日线猜测高低点先后顺序。

## 如何从500个候选走到模型

1. 按新目录实现并验证各方向，先跑有可靠日线来源的主效应，再核对资金流和财务。
2. 用Training内统计检查覆盖率、近常数、完全线性关系和高度冗余；逐窗口执行，不能先用所有年份选因子。
3. 500是研究候选预算，不是最终必须保留的列数。若某个方向有效信息少，应减少数量，不用窗口变体或复制符号补名额。
4. 更多列会影响正则化与家族暴露；采用分组消融和统一验证条件比较，不能让80列的家族自动被解释为“比35列家族重要”。最终按增量样本外信息与净成本回测判断贡献。
5. 当前交付不使用永久Test，也不改变先做特征、后做模型的顺序。

检查脚本已确认：500条记录、500个唯一名称、500种字面公式、原50列均保留、25个交互所引用的父因子均存在。字面公式不同不代表不存在代数关系或经验相关，语义冗余仍需计算后检查。

## 参考依据与适用范围

- [Microsoft Qlib Alpha158官方实现](https://github.com/microsoft/qlib/blob/main/qlib/contrib/data/loader.py)：支持把K线、价格、成交量及滚动价量统计分开组织的工程思路。新清单不是复制Alpha158，也不声称其效果可直接迁移。
- [Medhat与Schmeling：Short-term Momentum](https://cepr.org/publications/dp15857)：报告换手水平下短期动量/反转存在差异，支持将活跃度视为条件而非预先断定低活跃数据无用。
- [NBER：Reversals and the Returns to Liquidity Provision](https://www.nber.org/papers/w30917)：研究流动性不同维度与短期反转的关系，支持流动性作为独立研究方向。
- [AQR：Quality Minus Junk](https://www.aqr.com/insights/research/working-paper/quality-minus-junk)：支持企业质量作为独立信息方向；不证明财务因子对本项目5日收益有效。

这些资料提供方向依据，**不提供本项目80/65/60等数量，也不证明此500库能盈利**；具体配额与公式组合是本项目的设计判断。
