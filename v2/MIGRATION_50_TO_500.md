# 从旧50因子训练迁移到当前500候选

本次修改针对训练适配，不是再增加因子。

| 原50因子的部分 | 500因子下如何处理 | 当前代码 |
|---|---|---|
| 写死旧FACTOR_COLUMNS与旧数据集 | 新入口只认当前平衡500目录；输入不足500列立即报错 | run_research.py、feature_model.py |
| 旧训练期中位数、截尾和标准化参数 | 每个新训练折重新拟合；不复用50因子的统计量 | research_controls.py |
| 固定系数长度/靠位置预测 | 按该折有效列动态拟合；保存每个系数的因子名称；预测按名称重新排列 | feature_model.py |
| 模型文件只存系数 | 同时保存500目录哈希、全部预处理参数、有效列名及系数映射；不兼容目录立即拒绝 | bundle_model / predict_frame |
| OLS | 保留无权重、无正则控制；500因子更易共线，所以另比较正则化线性模型 | run_research.py |
| MSE、MAE、Huber | 数学定义不随特征数改变；重新训练系数，Huber尺度仍只从新训练标签估计 | linear_losses.py |
| L2、Huber阈值 | 不因50变500机械乘十；初始值只是对照配置，最终必须在新500体系下重新做时间验证 | --l2 / --delta |
| 日期/股票权重 | 是样本权重，不是因子权重，算法不因特征数改变；继续在当前训练样本计算 | research_controls.py |
| Rank IC与交易规则 | 保持共同评价口径才能比较新旧模型；不因输入变500而改变评分规则 | research_controls.py、simulation.py |
| 旧运行入口 | 默认拒绝误跑；旧实验需显式 --legacy-50，新研究用run_research.py | train_linear_baselines.py |

500是输入候选数，不要求500列强行参与回归。现有数据50个财务相关候选被隔离；可用450列再经训练期质量/冗余筛选，当前小样本剩447列。保存的系数数量随训练折实际有效列数改变。

新入口：`E:\Anaconda\envs\quant_ml\python.exe v2\run_research.py`。默认使用`quant_data/processed/v2/balanced_500`；该全市场目录尚未生成时，应显式指定已经生成的样本目录。资源限制与正式研究未完成事项见`IMPLEMENTATION_GUIDE.md`。

本轮兼容性验证输出使用新目录`quant_data/processed/v2/research_500_schema_verified`，不覆盖以前结果。旧模型文件不直接冒充新格式；需通过当前入口重新拟合。模型格式版本`balanced_500_linear_v1`与项目V1不是同一个概念。

验证已完成：19项数值/流程/输入兼容性测试通过；80只股票样本的10组模型和20组模拟重新跑通。全部10个保存模型重新加载后，对2023年1月数据打乱列顺序仍得到一致预测，且与修改前同配置预测一致。确认本次修复了模型输入与保存的可靠性，没有偷偷改变loss、权重或已有数值结果。这仍是小样本兼容性验证，不是全市场正式训练。
